## zola 开发心得

### 配置

zola 会校验文章内的 front matter，如果有重复项或错误，也会在启动时给予提示。zola 的自定义配置 key 必须在 extra 中定义，否则启动时 zola 会指出错误：

```bash
[extra](Error: Failed to build the site
Error: TOML parse error at line 16, column 2
   |
16 | [customer]
   |  ^^^^^^^^
   ......
```

### 分页

分页对象只有 section 中有，且该 section 或父 section 的 `paginate_by` 参数必须为正数。

### 未知变量调试

当你不知道如何使用某个函数的返回对象包含哪些参数时，可以填写必要参数完成调用，拿到返回值然后使用 `json_encode` 打印出来。例如 `get_section`，可以这样写：

```html
{% set posts_section = get_section(path="post/_index.md") %}
{# 需要使用 pre 块包裹 #}
<pre>
  {{ posts_section | json_encode(pretty=true) }}
</pre>
```

### 网站 icon

zola 会自动读取 `static/favicon.ico` 文件作为网站的 icon。

## zola 内置支持

### [文件名日期前缀解析][zola-date-filename]

zola 支持指定日期格式的文件名解析，这样不需要在文章内部的 front-matter 中添加 date 了。

目前仅支持使用 `yyyy-mm-dd` 格式的前缀，datetime 后可以使用 `-` 或 `_`，然后跟文件的名称。格式形如 `yyyy-mm-dd-title.md` 或 `yyyy-mm-dd_title.md`。如果文件名和和 front matter 中都有符合格式的日期，以 front matter 为主。

## zola 文章编写建议

### 建议每篇文章的 front matter 都包含以下参数

```yaml
---
title: xxx
date: yyyy-mm-dd
taxonomies:
  categories: [A]
  tags: [b, c]
---
```

### 少建目录，归类可以共同的开始为起始字母

例如 linux 教程，文件名可以为 `linux-xxxx.md`，少一个目录就少一个 `_index.md` 繁琐步骤。
